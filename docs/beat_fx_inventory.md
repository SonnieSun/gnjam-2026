# 三关物品的美术效果，以及统一节拍接口的计划

整理时间：2026-11-15，读的是 `develop_kisa` 当前工作区的代码。只读，没改代码。路径和作者见同目录 `asset_list.md`。

## 怎么看「驱动方式」

| 记号 | 意思 | 和音乐的关系 |
|---|---|---|
| **拍** | 每帧读 `Conductor.song_beat` 算出来 | 已经和拍子对齐，永远不漂 |
| **秒** | 用 `delta` / Tween / 固定秒数在走 | 和拍子无关，换 BPM 会对不上，时间长了可能漂 |
| **事件** | 打中、Miss、按键时触发 | 跟玩家走，不跟音乐走 |
| **进度** | 跟积累条进度走 | 跟玩家打得多少走 |
| **静** | 不动 | |

现在的情况是：大部分「跟拍」的效果已经读的是同一个节拍时钟，**但每个效果都写死在各自关卡的舞台脚本里**（`disco_stage.gd` 的 `update()` 里一口气算十几样东西），音乐系统找不到它们，也没法统一改「几拍一次、跟哪条音轨」。框架里唯一能单独挂的节拍效果是 Sonnie 的 `BeatGlow`（`scripts/fx/beat_glow.gd`），目前只有迪斯科路上的水果在用。

## 统一节拍接口：改动清单（等你确认再写）

### 目标

场景里任何物品挂上同一种接口以后：
1. 音乐系统能找到它（全局查得到所有挂了接口的物品）；
2. 它的效果（闪、胀、动画、换色……）按统一的规则跟拍：几拍一次、错开几拍、跟哪条音轨；
3. 现有关卡脚本不用知道它存在。

### 做法

- **新建一个节拍效果组件 `BeatFx`**：挂在物品下面当子节点，作用在父节点上（和 `BeatGlow` 用法一样）。Inspector 里选效果类型（胀缩 / 自发光闪 / 灯光闪 / 拖 AnimationPlayer 进度 / shader 参数 / 换色），以及「几拍一次、错开几拍、闪完掉多快」。
- **怎么被音乐系统找到**：组件进场景时自动加进 `beat_fx` 组，并按「频道」登记（例如 `beat`、`bar`、`kick`、`lead`、`fever`）。音乐系统或任何人用 `BeatFx.find("kick")` 就能拿到这一组物品，统一打开、关掉、改强度。
- **节拍从哪来**：只读 `Conductor.song_beat`，并接 `Conductor.beat / bar` 和 `Music.lane_switched / tier_changed / fever_started / fever_ended` 信号。**不改 Conductor 和 Music**，只接它们现有的信号。
- **「跟某条音轨」第一版的意思**：那条音轨现在有声音时才闪（用 `Music.playing_clip()` 判断）。要精确到「鼓点打在哪一下就闪哪一下」，需要每段 loop 的打点数据，现在音乐文件里没有，见下面的确认点 2。

### 需要你确认的点

1. **第一步先做组件 + 测试场景，可以吗？** 第二步改三关的文件，等第一步你看过再一关一关来。
2. **「跟音轨」要做到多细？**
   - A. 只要「每拍 / 每半拍 / 每小节 + 这条音轨开着才闪」：现在就能做。
   - B. 精确到音轨里每一下鼓点、每一个音：需要 EiZi 那边给每段 loop 出一份打点表（例如 `s1_C_drums_4b.json` 写哪几拍有鼓），要和 EiZi 协调。
3. **打中 / Miss 的反应要不要也走这个接口？** 例如「打中时这组物品一起闪」。走的话一个物品可以同时设「跟拍」和「跟判定」。
4. **现在写死在舞台脚本里的效果**（灯球、星星灯等，多数最后是 Sonnie 改的）：挪到组件上，还是保留原样、只在组件里登记一下让音乐系统能找到？后者不改效果、风险小，但两套写法会并存。
