# 叠轨音乐播放管理（设计）

> **已经做了的（2026-11-15）**：`Music` autoload（`scripts/music/music.gd`）和 Music Director 面板
> （`scenes/tools/music_director.tscn`，F6 运行）。每个大关的配置在 `levels/music/<大关文件名>.json`（如 `level_5.json`）。
> 下面"运行时"一节写的四个旋钮，第一版统一成了更简单的东西：**几条轨道，每条放几段 loop，同一时刻
> 只响一段；每个小关里写"积累条进度到哪儿换成哪段"**。详见文末"Music Director"。

目标：一关的音乐由几层 loop 叠起来，玩法推进时在小节线上加层、换层、换风格，节拍时钟不受影响。
素材见 `assets/audio/README.md`。下面是第一版要做的东西，先简单能用。

## 核心做法：一个同步流 + 只改音量

- 一关用到的**所有** loop（每层的每个版本）放进一个 `AudioStreamSynchronized`，从第 0 秒一起播放，
  永远不停、不跳。要"开一层"就是把它的音量从 −80 dB 拉到 0，要"换风格"就是 A 的音量降、B 的音量升。
- 这样所有层天然对齐（同一个混音循环里推进），不会有"后开的层慢几毫秒"的问题；loop 长度不同
  （4 / 8 / 16 小节）也没关系，因为都是整数小节，各自循环，永远对得上。
- **Conductor 不用改时钟逻辑**：它本来就是放一个 stream、读 `get_playback_position()` 算 `song_beat`。
  只要把它放的 stream 换成这个同步流。

已经在 Godot 4.7.2 里验证过（headless）：

- 打包时写进 WAV 的 `smpl` 循环点会被导入器读到，导入后 `loop_mode = LOOP_FORWARD`，循环整个文件；
- 三个不同长度的 loop 放进 `AudioStreamSynchronized` 一起播放，`get_playback_position()` 按真实时间
  往前走（7 秒时报 6.97 s），`get_length()` 是最长那条的长度（这里 24 s），可以直接给 Conductor 当一遍的长度；
- `set_sync_stream_volume(i, db)` 可以单独控制每条的音量。

限制：一个 `AudioStreamSynchronized` 最多 32 条。所以每关只放这关会用到的版本（第 1 关全部风格加猫化加
节奏型大约 30 条，正好装得下；爵士是另一套骨架，单独一关）。

## 数据：每关一个 MusicSet

`MusicSet`（Resource，存成 `.tres`，放 `levels/` 或 `assets/audio/music/<关>/`）：

| 字段 | 说明 |
| --- | --- |
| `bpm` | 160 |
| `layers` | 一组 `MusicLayer`：`slot`（槽位名）、`variant`（版本名）、`stream`（WAV） |
| `start_phase` / `start_style` | 开局状态 |

槽位（slot）就是"同一时刻只响一个版本"的位置：

| 槽位 | 第 1 关的版本 |
| --- | --- |
| `bed`（L0） | `futurebass` · `eurobeat` · `chip` · `disco` · `cat`（C_stabs） |
| `groove`（L1） | `four` · `half` · `break` · `club` |
| `bass`（L2） | `four` · `half` · `break` · `club` · `cat`（C_bass） |
| `hook`（L3） | `futurebass` · `eurobeat` · `chip` · `disco` · `cat`（C_lead） |
| `peak`（L4） | `futurebass` · `eurobeat` · `chip` · `disco` |
| `meowdrums` | `on`（C_drums，叠加层，没有别的版本） |
| `event_meow` / `event_seal` / `event_vox` | 事件层（X_meow、X_seal、X_vox） |

经典曲一关：`bed` = `fb_L0_keys` / `cat`（C_stabs）；`hook` = `pluck` / `cat_flow` / `cat` / `cat_pool`；
`bass` = `L2_bass` / `cat`（C_bass）；`peak` = `fb_L4_peak`；`meowdrums`；`groove` 用第 1 关的。

## 运行时：Music（autoload）

状态只有四个"旋钮"，每个旋钮的变化都**排队到下一个边界**才生效：

| 旋钮 | 值 | 生效时机 | 作用 |
| --- | --- | --- | --- |
| `phase` | 0–4 | 下一小节 | 开哪些槽：0 = bed+groove，1 = +bass，2 = +hook，3 = +peak，4 = 全开 |
| `style` | 风格名 | 下一个 4 小节边界 | bed / hook / peak 换成这个风格的版本 |
| `catness` | 0–4 | 下一小节 | 1 = +meowdrums，2 = bed→cat，3 = hook→cat，4 = bass→cat |
| `rhythm` | four / half / break / club | 下一个 4 小节边界 | groove + bass 换版本；谱面要同时换 |

接口（草案）：

```gdscript
Music.load_set(set: MusicSet)        # 建同步流交给 Conductor，按开局状态设音量
Music.set_phase(n: int)
Music.set_style(style: StringName)
Music.set_catness(level: int)
Music.set_rhythm(rhythm: StringName)
Music.trigger_event(slot: StringName, bars := 4)   # 事件层开 N 小节后自己关
Music.miss()                          # hook / peak 降 9 dB，一小节后回来
```

每个槽位当前应该响哪个版本，由四个旋钮算出来（`_target_variant(slot)`）。到边界时对每条子流比较
"该不该响"，该响的 10 ms 淡入，不该响的淡出 1 拍。

### 边界和淡入淡出

- 在 `_process` 里看 `Conductor.song_beat`：一越过排队的边界（小节 = 4 拍，4 小节 = 16 拍）就应用。
  为了不晚，提前 `AudioServer.get_output_latency()` 应用（和 Conductor 算时间的方式一致）。
- 淡入淡出自己在 `_process` 里按幅度线性插值，每帧调 `set_sync_stream_volume()`；−80 dB 当静音。
- 晚一帧（约 16 ms）开层，最多吃掉这一小节第一下的开头，听得出但不严重；第一版先这样，不行再改成
  提前一帧排程。

### 总线

| 总线 | 内容 | 效果 |
| --- | --- | --- |
| `Music` | 同步流 | 压缩器，`sidechain = "Kick"`：玩家打中时音乐让一下 |
| `Kick` | 玩家底鼓、拍手（DrumKit / Sfx） | — |
| `Sfx` | 猫叫单发、转场音效 | — |

同步流只能进一条总线，所以 MISS 的"变闷"第一版改成 hook / peak 降音量；真要低通，把 hook 和 peak
拆进第二个同步流放 `MusicTop` 总线，和第一个同一帧 `play()`（要实测两者对不对得齐）。

## 转场（和 Conductor 的小节信号配合）

| 时机 | 做法 | 素材 |
| --- | --- | --- |
| 第 20 小节（一关的最后一小节） | 除 groove、bass 外全部淡出；放上升音效 | `sfx/riser_1b.wav` |
| 下一小节首拍 | 镲；载入下一关的 MusicSet，从头播放 | `sfx/crash.wav` |
| 风格切换 | 切换前一小节第 4 拍放提示音 | `sfx/glitch_meow.wav`、`laser_zap.wav` |
| 猫化 +1 / −1 | 生效那一小节首拍 | `sfx/catness_up.wav` / `catness_down.wav` |
| 失败 | 音乐 `pitch_scale` 0.5 秒内降到接近 0（卡带停转），然后停 | `sfx/catness_down.wav` |
| 重来 | 倒带音效 1 小节，再从这一关第 1 小节开始 | `sfx/rewind_1b.wav` |
| 过关 | 第 20 小节后首拍用过关音效替代镲 | `sfx/level_clear.wav` |

单发音效对齐到拍子：在 `Conductor.beat` / `bar` 信号里放，或者算好下一拍的时间提前排。

## Music Director（已做）

编辑器顶部工具栏点"音乐"按钮（或打开 `scenes/tools/music_director.tscn` 按 F6）。面板有两页：

- **曲库**：只是听。列出现在所有做好的曲子（四种风格、全猫乐队、Jazz、三种节奏、Entertainer、五首经典曲和它们的猫版、鬼畜版），
  点一首就循环放，下面的按钮开关它的每条音轨；最下面是所有一次性音效（喵、打中喵、SFX），点一下听一声。
  加了新曲子在 `scripts/music/jukebox.gd` 的 `_songs()` 里加一行。
- **编辑**：给每个大关配音乐，下面说的都是这一页。

一关的音乐是几条**轨道**（默认按乐器分：节奏、低音、和声、旋律、高潮、猫鼓、事件），每条轨道里放几段
**片段**（loop），同一时刻每条轨道只响一段。

- **点一段** = 从当前进度起，这条轨道换成它；再点正在响的那段 = 从这里起这条轨道静音。正在响的那段是粉色的。
- **PROGRESS** 就是积累条有多满：先拖到某个进度再点，就是"进度到这里时换成它"。
  SNAP 开着时等到下一个小节线才换（和游戏里一样）；AUTO 让进度随音乐在 N 小节里从 0 走到 100%。
- 每条轨道下的**细条**：颜色是每段进度里响的片段，白色小竖条是切换点，粉线是积累条事件线。
  拖切换点改位置（吸附 5% 和事件线），右键删掉。
- **+ 片段** 往轨道里放 WAV（从 `assets/audio/music` 里选），右键一段 = 拿掉；**+ 轨道** 加一条，`×` 删一条；
  轨道名字可以直接改；M 静音（只在面板里）；dB 是这条轨道的音量。一大关最多 32 段。
- 上面：选大关、选小关（名字和积累条事件线取自谱面）、PLAY、当前小节、USE IN GAME、SAVE、
  **EXPORT MIX**（录一遍 AUTO，也就是这个小关从 0% 到 100%，存成 `levels/music/exports/level_<n>_<小关>.wav`，不进 git）。
- 快捷键：Space 播放 / 停止，← → 进度 ±5%，↑ ↓ 换小关，Ctrl+S 保存。

配置和大关文件同名：`levels/level_5.tres` 的音乐是 `levels/music/level_5.json`，以此类推。
新加一个大关，面板里打开它就会新建一份空配置。第 3、4 关都是 MV：`level_3.json` 是 future bass 版，`level_4.json` 是 eurobeat 版。

配置格式：

```json
{
  "title": "LEVEL 1", "bpm": 160, "use_in_game": false, "quantize_beats": 4,
  "lanes": [{"id": "bed", "name": "和声", "gain_db": 0,
             "clips": [{"id": "fb_keys", "file": "res://assets/audio/music/scene1/style_futurebass/s1_fb_L0_keys_4b.wav"},
                       {"id": "cat_stabs", "file": "res://assets/audio/music/scene1/cat_band/s1_C_stabs_4b.wav"}]}],
  "sections": [{"title": "DISCO", "cues": {"bed": [[0, "fb_keys"], [0.5, "cat_stabs"]]}}]
}
```

`cues` 里每条轨道是一串 `[进度, 片段]`：进度到这里换成这段（`""` = 静音）；当前进度之前最后一个切换点说了算，
一个切换点都没到 = 静音。初始配置由 `tools/music_gen/make_music_sets.py` 生成（第 1 关：future bass 越来越猫；
第 2 关：16 个小关轮流换风格，第二轮加猫；第 3、4 关：六个 MV 小关一关比一关猫；第 5 关：康康舞曲）。之后都在面板里改。

游戏里（`scripts/main.gd`）：配置开了 `use_in_game` 的大关，谱面的伴奏换成这套同步流、BPM 换成配置的；
进小关时（`section_entered`）`Music.set_section(i)`，积累条变化时（`gauge.changed`）`Music.set_progress(值 / 满条值)`。
没开的大关用谱面自己的伴奏和 BPM。现在五个大关都开了。第 5 大关（披萨）谱面的 BPM 是 160；第 1 到 4 大关（Kisa 的四关）谱面 BPM 是 120（它们原来伴奏的速度），开着叠轨音乐时按配置里的走。

## 音乐的档次（设计，2026-11-15）

一关的音乐按"有多猫、有多满"分档，积累条越满档越高。常态是**音乐 + 猫鼓 + 猫主旋律**；别的猫声部是点缀。

| 档 | 什么时候 | 响什么 |
|---|---|---|
| 0 开场 | 刚进小关 | 鼓 + 低音（可以带和声） |
| 1 音乐 | 积累条刚起来 | + 和声、乐器旋律 |
| 2 猫鼓 | 约三分之一 | + 猫鼓（先于猫旋律进） |
| 3 猫旋律（常态） | 约一半 | 乐器旋律换成猫主旋律（喵放完、互相叠的那版） |
| 4 高潮 | 约四分之三 | + 高潮层 |
| 5 KIAI | 最后 5%–15%，或特别的时刻 | 鬼畜猫旋律**叠在**猫主旋律上面。克制地用，短，一关一两次 |

- **猫和声、猫低音**少见：只在某一关的最后一段当"全猫"的颜色用，不是常态。
- **一关里换不换音轨**：小关之内，轨道跟着积累条换片段（上表）。小关之间可以换风格或换节奏型（比如迪斯科关拆房子时鼓换成 club、
  和声旋律换成 future bass），但同一大关用同一个调、同一个速度的素材，这样随时能切。每个小关会从头重新叠；后面的小关可以从 1、2 档起步，不必回到 0。
- **速度**：一个大关一个速度（配置里的 `bpm`）。现在所有开了叠轨音乐的关都是 160（迪斯科关原来是 120，2026-11-16 改成了 160；120 的那套素材 `scene1_120` 还留着，曲库里能听）。

### KIAI 现在怎么做的

每条轨道同一时刻只响一段，所以要"叠"就得放在不同轨道：配置里多了一条 **KIAI 鬼畜** 轨道，里面只有鬼畜猫旋律，
切换点放在很靠后的进度；旋律轨道上的猫主旋律照常响，两条就叠在一起了。KIAI 轨道音量 -2 dB。
现在用上的：迪斯科关的飞碟结尾（最后 5%）和吸猫小关的最后 15%；第 2、4 关最后 10%；第 3 关山魔王最后 10%。

### 以后再做（现在没做）

- KIAI 由别的东西触发，而不是只看进度：连击到里程碑、积累条刚满的那一小节、关卡脚本主动喊一声（`Music` 加一个"开 N 小节 KIAI"的接口）。
- KIAI 时把乐器旋律和高潮层压低一点（让猫更突出），结束后放回来。
- 小关之间的过门：切小关前一小节放 riser / 倒放，切过去第一拍放 crash 和一声长喵。
- 掉血时的反应：连续 Miss 时退一档，而不只是跟着积累条慢慢掉。
- 运行时猫旋律（见上一节）做好之后，KIAI 的鬼畜层可以换成玩家打出来的。

## 喵谱子：在游戏里写猫鼓和鬼畜猫旋律（2026-11-15）

它们**不替换**原来预渲染的猫鼓和猫旋律，只是多出来可以选的片段。

- **在哪写**：**曲库**是总入口（游戏里按 Tab 点 **Jukebox**，或打开 `scenes/tools/jukebox.tscn` 按 F6）。
  曲库里多了一排"喵谱子"：存好的谱子都列在这里，点名字 = 跟着现在放的曲子一起放，点 ✎ = 在**喵谱子工作室**
  （`scenes/tools/meow_studio.tscn`，全屏）里打开编辑；"+ 新猫鼓 / + 新旋律"也在这一排。
  工作室是独立的：PLAY 默认只放谱子本身，按上面的 BPM 自己走，不放曲子，可以勾节拍器。
  想配着别的音轨听，就在"伴奏"里选曲库里的任意一首，下面一排是它的每条音轨，点亮哪条就加哪条进试听。
  Tab 面板上还有一个 **Meow** 按钮直接进工作室。
  - **New drums**：猫鼓，每行一种喵（低喵、高喵、只用开头一下的"mi"），点格子 = 响 / 不响。
  - **New melody**：鬼畜猫旋律，小钢琴卷帘（A3 到 E6）。点 = 放一个音，往右拖 = 拉长，右键 = 删掉；同一时刻只有一个音。
    Cat 选哪只猫唱，auto = 每 4 小节挑原本音高离这一句最近的那只。
  - **PLAY** 之后谱子一直循环，边改边听。**Save** 存成 `levels/music/patterns/<名字>.json`，存了就出现在曲库里。
  - **MIDI 键盘**：插着的话，按键就试听那个音；PLAY 的时候按，音符直接录进旋律（对齐到 16 分音符，松手决定长度，
    弹得太高太低会挪八度放进猫的音区）。猫鼓谱子里，从中央 C 起一个键对应一行。
- **怎么用进关卡**：工作室只管写和存。回到游戏按 Tab，**Music** 页每条轨道右边有一个 **+ meow**，
  从里面选一个存好的谱子，它就成了这条轨道的一个新片段，和别的片段一样点它来按进度切换；点右上角 Save 写进这一关的配置。
- **从 MIDI 来**：`python tools/music_gen/midi_to_pattern.py 曲子.mid --name 名字`，旋律就出现在工作室的谱子列表里。
  它只要 Python，不要采样，谁都能跑：取音符最多的那一轨、每个时刻留最高的音、对齐到 16 分音符、整体挪八度放进猫的音区。
- **想要高质量的预渲染版**（拉长的 Miiiiao、互相叠）：在有采样的电脑上
  `python -I render_pattern_leads.py <谱子.json> <loops 目录>`，出"喵放完 / 切到音符 / 鬼畜"三条 WAV。
- **怎么发声的**（`scripts/music/meow_player.gd`，`Music.meow`）：每只猫一个采样（`assets/audio/meows/runtime/`，
  共鸣已经烤进去，由 `make_runtime_meows.py` 生成），用 `pitch_scale` 变速变调到要的音高，音符结束就停掉。
  所以换速度不用重渲染。触发提前了一个输出延迟，尽量落在格子上，但精度是一帧左右（10–20 毫秒），比预渲染的松一点。
- **配置里的样子**：片段写成 `{"id": "名字", "pattern": "res://levels/music/patterns/名字.json"}`（普通片段是 `"file"`）。
  谱子片段不占同步流的 32 条名额。
- 自带两个起步的：`meow_drums_basic`（猫鼓）和 `kichiku_riff`（第 1 关那条旋律）。

## 五档和动态（2026-11-16，已经在跑）

### 每首曲子的五档

积累条越满档越高，档位线默认在 20% / 45% / 70% / 90%（配置里每个小关的 `"tiers"`）：

| 档 | 名字 | 响什么 |
|---|---|---|
| 1 | 弱版 | 鼓、低音、和声 |
| 2 | 弱喵 | + 乐器旋律；猫只回应玩家：有"打中唱"的谱子片段时，玩家每打中一下，猫唱出旋律的一个音 |
| 3 | 强版 | + 高潮层、猫鼓 |
| 4 | 全喵 | 猫接过旋律（猫主旋律）、和声、低音 |
| 5 | 鬼畜全开 | 鬼畜猫旋律叠在猫主旋律上（KIAI 轨道） |

猫旋律在高音区（G5 以上）会叠一声鬼畜喵：保共振峰的喵到了高处会变细、听不出音高，所以用变速的喵把它描一遍，越高叠得越响。

本来就鬼畜的曲子（模板里 `native=True`）：从第 2 档起旋律就是鬼畜版，第 5 档改成把猫主旋律叠上去。
模板在 `tools/music_gen/make_music_sets.py` 的 `five_tiers()`；飞船、电视墙、披萨三关是用它生成的。迪斯科关是按它自己的 9 条事件线手调的，没套模板。

### 换音轨的动态（`scripts/music/music.gd`，配置里写 `"dynamics": false` 整套关掉）

- **升档有过门**：进度过了档位线，换之前先放一声上扬音效（变速，正好在换的那一拍放完），换的那一拍放镲和一声上扬的喵。
- **降档迟钝**：进度要掉到档位线以下 6% 才真的退一档，退的时候放一声往下的喵。在线附近抖不会来回切。
- **旋律等乐句线**：`lead` 和 `kiai` 轨道从一段换到另一段，等到 4 小节的线才换（轨道上写 `"quantize_beats"` 可以改）；
  从没声到有声、或者要静音，仍然是下一个小节线。别的轨道都是下一个小节线。
- **档位线**：小关里写了 `"tiers"` 就用它，否则所有切换点的位置都算一条线。

### 音游的动态（`scripts/music/hit_meow.gd`，main.tscn 的 HitMeow 节点上调）

| 玩家 | 声音 |
|---|---|
| 打中 | 打中喵；如果"打中唱"的片段在响，改成唱出旋律里离现在最近的那个音 |
| 连着打中之后第一下漏打 | 一声 miss 喵，`lead` / `kiai` 轨道压低一拍。一直漏打不会一直响 |
| 连击断了（断之前 ≥ 10） | 一声 glitch 喵，旋律压低两拍 |
| 连击到里程碑 | 转圈喵；到 50 以上的里程碑，再送 4 小节鬼畜全开（`Music.kiai(4)`） |
| 积累条满了 | 一声上扬音效，正好在换小关的那条小节线上放完（`Music.rise_to_bar()`） |

**打中唱**：轨道里的谱子片段写上 `"by_hit": true`（`{"id", "pattern", "by_hit": true}`），它就不自己按格子响，
玩家每打中一下，才唱出旋律里离现在最近的那个音（前后 3 格以内）。飞船和电视墙两关的第 2、3 档用的是 `kichiku_riff`。

### FEVER 和小 kiai

- **FEVER 是手动设计的**：在某个小关的配置里写 `"fever": [从, 到]`（积累条进度 0–1；可以写好几段 `[[a, b], [c, d]]`）。
  进度走进这一段：先一小节过门（配置里有 `fill` 轨道的话），然后 fever 开始 —— 鬼畜猫旋律（`kiai` 轨道）和"打中唱"（`hit` 轨道）
  全程开着，不管它们自己的切换点怎么写。走出这一段就结束：往上走完，或者掉回去（掉回去同样迟钝 6%）。
- **信号**：`Music.fever_started` / `Music.fever_ended`，画面和得分想跟着 fever 走就接这两个；`Music.fever` 是现在在不在 fever 里。
  还有 `Music.tier_changed(new_tier, up)`，每次升降档发一次。
- **现在放在哪**：迪斯科关放在**圆台**的后半段（积累条 280–350 / 430，圆台那条线是 250，结尾镜头那条线是 320）；
  模板生成的三关（飞船、电视墙、披萨）放在最高一档（90% 以上）。挪位置就改那个 `"fever"`。
- **小 kiai**：每次升档，鬼畜猫旋律响一小节就退（fever 里不重复送）。连击到 50 以上的里程碑送的 4 小节也是它。

### 所有切换都在小节线上；过门小节

规则：**换片段、换档、换小关，一律落在小节线上**。没有哪种切换会在小节中间发生（漏打时旋律压低一下是音量，不算切换）。

有的切换前面再加一小节**过门**：配置里有一条 id 是 `fill` 的轨道（里面放过门音轨 `s1_X_fill`，160 和 120 各一条：
拍手从八分加密到十六分、小猫 mi-mi-mi-mi 往上爬、底下一条噪声上扬；没有和声和低音，所以配任何曲子）时，

- **换小关**：小关在小节线上换，这一小节只响节奏轨 + 过门，下一条小节线新小关的音乐才进来。
- **升到指定的档**：小关里写 `"transition_tiers": [3]`，升到第 3 条线（猫接管的那一档）时，先一小节过门，再下一条小节线才换。
  模板生成的三关（飞船、电视墙、披萨）都是这样。

想给某首曲子单独设计过门小节：做一条和它等长的过门音轨（每小节都是过门），放进 `fill` 轨道就行。

### 曲子的段落

一首曲子可以有几个段落（前奏、A、B、结尾），调和速度相同，所以它们的音轨可以放进同样的轨道，在乐句线上互相换。
《Your Best Friend》现在有四段素材：`your_best_friend`（主题，8 小节）、`ybf_intro`（前奏，4 小节）、`ybf_b`（B 段，8 小节）、
`ybf_end`（结尾，4 小节，放一遍不循环）。前奏的引子来自原曲，B 段和结尾是按它的和声给这个游戏写的。
把段落用进关卡的两种办法：每个小关用一段（小关 = 段落）；或者同一个小关里，轨道在某一档从 A 的音轨换到 B 的音轨。
结尾段在通关时放一遍，这个还没接进游戏。

### 不同曲子之间怎么衔接（设计）

两首曲子调不一样，所以**不让两首的和声同时响**，靠没有音高的东西过渡：

1. **同一个速度的两首（都是 160）**：上一首的最后一小节换成过门小节（只有鼓 + 过门，没有和声），下一条小节线新曲子从第 1 档进来。
   鼓不断，听起来是一口气；和声在过门那一小节里是空的，所以换调不会打架。现在的"换小关过门"做的就是这件事，
   只要两首曲子的音轨都在同一关的配置里（同一个同步流，最多 32 段）。
2. **速度不同的两首（160 ↔ 120）**：没法无缝，就明着切：上一首放结尾段或过门小节，停一拍（一声 rewind / 转圈喵），新曲子从前奏段起。
   现在一个大关只能一个速度，所以这种衔接发生在大关之间，换关时本来就会重新开始。
3. **想更顺**：给下一首做一个 1–2 小节的引子（只有它的低音或一个长和弦），接在过门后面；或者把两首曲子渲染成同一个调（渲染时整体移调就行）。

| 进度 | 阶段 | 音乐 |
|---|---|---|
| 开头 | 云层 | 半拍的鼓、一个低音长音、穿云的风（一阵阵云从左到右掠过）。每打中一下猫唱一个音，一路往上爬（`ufo_rise`，C 小调五声） |

| 50% | 亮起来 | 小节线上所有黑的东西一起停，一声"神圣的和弦"；然后正常的鼓、欢乐颂的和声和低音、神圣长音（大三和弦 + 猫合唱 + 铃）。**每打中一下唱出欢乐颂的下一个音**（`ode_to_joy` 谱子） |
| 70% | 太空 | 旋律自己响了：猫唱欢乐颂，+ 猫鼓 |
| 85% | 进 UFO，FEVER | 一小节过门，然后 + 高潮层、鬼畜猫旋律，打中还在唱 |

写一个不存在的名字（`"none"`）就是什么都不放。

## 关与关之间：过门和喘息（已经接上）

一路连着玩时，一关打完到下一关开始是这样的：

1. **打完**（`main.gd` 的 `_clear_level`）：`Music.bridge_out()` —— 一声"飞走"（上扬的扫频 + 一声往上滑走的喵），同时起一段等待的循环
   （风、慢慢的心跳、一个低音）。音乐停，换场景。`Music` 是自动加载，换场景不会断，加载那零点几秒里声音照常响。
2. **喘息**：下一关的场景出来了，但不开始，屏幕上是关卡名和 PRESS TO START，等待的循环一直响。
   想在这里放转场动画（黑幕落下、猫飞上天）就接在这一段。
3. **玩家按一下**（打鼓的键或鼠标）：`Music.bridge_go()` —— 一小节数拍子（四声往上的 mi），等待的循环在这一小节里淡出，
   数完正好是下一关的第一拍。

每一个接口都是同一套（2026-11-16 统一，同一天改成"喘息在下一关的场景里"）：
- **黑幕**：打完之后黑幕从上往下落下来（`main.tscn` 的 `curtain_seconds`，0.6 秒）再换关；关卡自己已经落过了（迪斯科结尾）就直接换。
  下一关的场景一摆出来，黑幕就接着往下落出屏幕（`StageCurtain.LEAVE_SECONDS`，0.9 秒）。
- **喘息在下一关真正的场景里，不在黑幕里**：下一关的第一个小关先摆在那儿（不开始，没有音符，分数和积累条藏着），
  画面下方是关卡名。停 `breath_bars` 小节（`main.tscn`，默认 1）之后自动开始数拍子；这段时间里按一下就马上开始。
  `breath_bars = 0` = 不自动开始，一直等玩家按（这时提示 PRESS TO START）。
- **下一关的声音透出来**（`Music.bridge_tease()`）：喘息时，下一关开头那条和声（没有就低音、再没有就鼓）小声地循环，
  和等待循环的小节对齐，2.5 秒淡进来，等待循环自己让开一点；开始数拍子时和等待循环一起淡出。多响在 `music.gd` 的 `TEASE_DB`。
- 最后一关打完没有黑幕，直接结算。

上面第 2、3 步说的"等玩家按一下"现在默认是"停一小节自动开始"。

不是一路连着玩（从暂停转盘选关、编辑面板试玩）就没有这一段，直接开始。

### 换曲子的规矩（2026-11-16 定的）

- **可以换曲子，但每一次换都要有专门写的一小节变奏过门**，不用通用的过门。没有它的时候（山魔王直接切康康舞）听起来像出错了。
- 变奏过门是一个一次性音效（`assets/audio/sfx/tr_*.wav`，`tools/music_gen/make_transitions.py` 做的）：用要走的那首曲子的动机做一个
  小变奏，一路走到新曲子的调上。里面**没有鼓**（关卡自己的鼓照常响；一次性音效可能晚几毫秒，两套鼓会打架）。
- 在小关的配置里写 `"enter": "tr_ybf_to_mk"`。换到这个小关的那一小节：鼓照常，上一首的和声、低音、旋律都让开，放这个音效；
  下一条小节线新曲子进来。
- 一首曲子的各条轨道不要一条一条地换成另一首的（或者它自己的 B 段）：换的那几小节里和声和旋律对不上。
- 现在有三个：

| 音效 | 从 → 到 | 写的是什么 |
|---|---|---|
| `tr_ybf_to_mk` | 小花（降 A 大调）→ 山魔王（A 小调） | "笑容裂开"：小花开头那一句先由乐器弹一遍，再升半音由猫鬼畜地唱一遍，落在 E（A 小调的属音）上，底下 E7 涨起来 |
| `tr_mk_to_cc` | 山魔王（A 小调）→ 康康舞（G 大调） | "大厅炸开"：山魔王那句蹑手蹑脚的开头变成十六分音符一路往上跑，半音爬到高音 D，底下 D7 涨起来，最后一声喵往上滑 |
| `tr_tm_to_cc` | 土耳其进行曲（A 小调）→ 康康舞（G 大调），第 3 关 | 进行曲的回音音型连着三遍，一遍比一遍高，然后 D7 琶音上去 |

- **洗衣机这一段积累条不涨**，音乐的进度是"按完了几次长按 / 一共要按几次"：关卡脚本每帧调 `Music.override_progress(p)`
  （换小关自动取消）。别的"不靠积累条推进"的小关也可以这么用。
- **一关里有几首曲子时**，每个小关写明自己的鬼畜和打中唱是哪一段：`"own": {"kiai": "cc_kichiku", "hit": ""}`
  （"" = 这个小关没有）。升档送的小 kiai、连击里程碑的 kiai、fever 里自动补的轨道都按它来，不会拿错成别的曲子的。
- **连按唱鬼畜（runtime）**：拍地球的连按段，每按一下猫唱出现在这首曲子的下一个音，按多快唱多快，上一个音硬切；
  每一串连按接着唱下一小节、换一只猫；超过达标数之后每多按一下整体升一个半音。`MeowPlayer.sing_step()`；
  谱子是 `levels/music/patterns/mountain_king.json` / `can_can.json`（从曲子的音符直接写出来的，没有渲染）。
  在 `earth_slap.tscn` 根节点的"连按"一栏调：`mash_sings` 关掉就回到原来一下比一下高的声音。
- **洗衣机的音效**（都是现成的）：开场猫头从画面上方转着飞进舱门，一声往下掉的喵正好掉到落进去那一下，落进去"咚"一声 + 转圈喵；
  每次长按一声上扬的音效，正好在该松手时放完；电视亮起来"滋"一声。
- **朋克运镜**（`tv_wall_intro_stage.gd` 的"朋克运镜"一栏）：Kisa 原来的跟拍运镜随着进展越来越疯——角度幅度最多乘 2.4 倍，
  远近一近一远地跳（0.5～1.5 倍），换镜头从每小节一次变成每 2 拍、每拍一次，而且越来越"硬"；每次打中镜头猛推一下。
  `punk_camera` 关掉就是原来的强度。

## 曲子从自己的第 1 小节起播；换曲子从强的地方起（2026-11-16 试玩之后）

**曲子组。** 以前所有片段在一个同步流里共用一个播放位置，一首曲子不管什么时候进来，都是从循环的中间接上（听着像从第二小节开始唱）。
现在片段上写了 `"tune": "ode"` 的，同一首曲子的几条轨道单独一个同步流、自己的播放器：这首曲子从"都没响"变成"有一条要响"的那条小节线，
从自己的第 1 小节放起；都不响了就停，下次进来又从头。比如欢乐颂在"亮起来"的那一刻从第一个音开始。
- 两个播放器走同一个音频时钟，不会越走越偏。起播时按节拍时钟算好从第几秒放起，实测和鼓差几毫秒；差多了会自己对回去。
- 这首曲子的喵谱子（和声、打中唱）也从同一条小节线算起。
- 哪个片段属于哪首曲子：生成脚本按片段名的开头分（`TUNES`）。第 1 关的配置没写，行为不变。
- 给谱面用：`Music.tune_origin("ode")`，见 `docs/music_chart_handoff.md`。

**换曲子从强的地方起。** 洗衣机 → 拍地球、射击 → 披萨这种，前后都是小高潮，新曲子不从空的地方重新铺：变奏过门那一小节之后，
新曲子进来就带着鼓、低音、和声和旋律。拍地球三段是一个想法的三步：只有主题（4 小节，乐器先弹、一半时猫接过去）→ 完整的曲子
（主题 + 应答 8 小节，猫 + 和声 + 高潮层）→ 康康舞。

**同一首曲子里旋律不断。** 披萨那段镜头换九宫格、换万花筒的时候，猫的旋律不换手、不停：靠往上加东西来标记（高潮层、乐器叠上来、
换猫鼓）。进 fever 前那一小节过门旋律是停的，曲子不换的小关写 `"fever_fill": false` 把它关掉。

## 场景里换阶段的规矩：旋律从头就在、中途不断（2026-11-16 第二次试玩之后）

"场景"= 玩家看到的同一个地方。换场景有专门的过渡（变奏过门、过场动画的过门）；**同一个场景里换阶段，主旋律不能被切掉**。

1. **曲子一开始就有旋律。** 一首曲子从哪里起，旋律（乐器或者猫）就从那里的第 1 小节起。"越打越满"是往旋律的下面和周围加东西，
   不是打一会儿才等来旋律。（以前：欢乐颂亮起来之后要打到 70% 猫才唱；洗衣机、射击段开头只有鼓和和声，旋律后来才从循环中间插进来。）
2. **旋律一旦响了，这个场景里就不停。** 没有哪个切换点把旋律拿掉，也不放过门小节（过门那一小节旋律是停的）：
   `transition_tiers` 空着、`"fever_fill": false`、同一个场景里接着走的小关写 `"enter_fill": false`。
3. **旋律可以换手**（乐器 → 猫，猫 → 鬼畜），是接过去，不是断开再起。换到另一首曲子的片段时旋律和别的轨道一起立刻换，
   不等乐句线（那首曲子是从这条小节线重新起的）。
4. **往下减的阶段**（安静的结尾）减和声、鼓、高潮层，旋律留着。第 1 关最后外星人出来那一段：以前旋律停了只剩鼓和和声，
   现在猫的旋律接着唱，去掉的是和声和猫鼓。
5. **进 fever 换段落**（射击段换到土耳其进行曲第二段）：不放过门，等到前一段的 4 小节乐句线上直接换（`"fever_on_bars": 4`）。

检查：`python tools/music_gen/check_music_sets.py .` 打印每一关每个阶段响什么，旋律中途停了、或者曲子起来时没有旋律会标出来。
现在只剩一处被标：第 1 关最开头（房间里只有鼓和低音，到灯球出现才进旋律），这是当初设计的"一开始平静"，留着没动。

这次按规矩改的：
- 上升关：亮起来的那一小节猫就开始唱欢乐颂（原来是"每打中一下唱一个音"，70% 才唱）；fever 时主唱不停，鬼畜叠在上面。
- 洗衣机：小花的旋律从第 1 小节就有（乐器），一半时猫接过去。
- 射击段：土耳其进行曲的旋律从第 1 小节就有；鬼畜进来之后乐器旋律垫在下面。
- 拍地球：第一段到第二段不放过门。
- 第 1 关：结尾旋律不停；广场 fever 前不放过门，fever 里猫主唱垫在鬼畜下面。房子打开那一下的过门留着（那是过场）。

## 换小关不掉到空；过关有收尾（2026-11-16）

**换小关时带着强度过去。** 以前新小关一律从进度 0 起，上一段打到全开，一换段就只剩鼓和和声，像音乐塌了。现在：
- 上一个小关走的时候有多满，新小关就带着它的六成进来（过门那一小节之后），再用 8 小节慢慢落回玩家在新小关里真正的进度；
  玩家打得快，真实进度先追上来，就感觉不到落。
- 带过来的只影响各条轨道响哪一段，不算档位，不会触发 fever、升降档的音效和小 kiai。
- 带几成：小关里写 `"carry": 0.6`（0 = 这个小关故意要从头安静地起），不写用整关的 `"carry"`，再不写是 0.6。
  落多久是 `music.gd` 的 `CARRY_BARS`。

**过关的收尾。** 一关打完，音乐停的那一下放一个这首曲子调上的收束：主和弦一大下（底鼓 + 镲）、猫在主音上一声 MIAO、
后面两声小的 mi 和高八度的一声。小关里写 `"exit": "end_g_major"`，没写就放通用的过关音效。
现在有三个调的（`assets/audio/sfx/end_*.wav`，`make_transitions.py` 做的）：G 小调（第 1 关的迪斯科主题）、C 大调（上升关的欢乐颂）、
G 大调（康康舞：第 2 关和第 3 关的结尾）。最后一关打完是直接出结算、音乐继续放，所以那里不放收尾。

## 猫唱歌：从 Mewgenics 学到的，和我们的做法（2026-11-16）

### Mewgenics 是怎么做的

没找到开发者公开讲实现的资料。下面是从本机安装的游戏文件里看到的（只读了资源包的文件表、几个配置和 MIDI，
没有导出或使用它的任何素材）。

**直接看到的：**
- **每首曲子带一个人声 MIDI。** 音乐配置里每个区域除了几条 ogg（地图、战斗、Boss、事件），还有一条 `midi`。
  MIDI 里不是伴奏，是专门给猫唱的两条轨：主唱（lead vocal）和和声（BGV）。它覆盖整首歌（600～800 拍），
  速度和 ogg 一致，是作曲时从工程里导出来的。主唱多是一拍左右的长音，和声是半拍的短音。
- **每只猫的"唱歌"采样只有一个**，而且就是它平时的普通叫声（219 套嗓音里 198 套只指定了一个文件）。
  长 0.3～0.9 秒，各自的音高从 195 Hz 到 1500 Hz 都有。没有专门录的唱歌素材。
- 程序里有 `SingingController`、`SingingCat`、`MidiResource` 这几个类，一个 "Singing Cat Test" 调试场景，
  一个 `EnableCatSinging` 开关。音频库是 FAudio。
- 每只猫生成时有一个随机的嗓音音高偏移（`voice_pitch_range`）。

**推断的（没有反汇编验证）：**
- 变调就是改播放速度（FAudio 的变调方式），整段采样变速，不保共振峰。所以听起来是鬼畜的质感。
- 配置里没有写每个采样是什么音，所以要么加载时自动测音高，要么只按相对音程变调。
- 控制器把两条轨的音符分给场上的猫，具体怎么分看不出来。

**它听起来干净的两个原因：** 采样很多是人配音的"喵"，音高稳；有独立的和声轨，主唱不用一只猫硬撑所有的音。

### 我们现在的做法

和它是同一条路（谱子 + 每只猫一个采样 + 运行时变调），差别和取舍：

| | Mewgenics | 我们 |
|---|---|---|
| 谱子 | 作曲时导出的人声 MIDI，整首歌 | 喵谱子（`levels/music/patterns/*.json`），4～16 小节循环；可以从 MIDI 导入 |
| 声部 | 主唱 + 和声两轨 | 主唱（预渲染的鬼畜猫旋律）+ **和声轨**（运行时的喵谱子）+ 猫鼓 |
| 采样 | 每只猫一个平时的叫声，不加效果 | 每只猫一个，烘了音高共鸣（真猫的叫声音高不稳，不加共鸣听不出音） |
| 嗓音 | 219 套 | 8 只真猫 |

五种唱法做过对比试听（`tools/music_gen/make_choir_tests.py`：现在的 / 纯变速不加效果 / 加和声 / 三只猫合唱 /
现在的加和声），选的是**"现在的 + 和声"**。

### 猫和声轨

配置里 id 是 `harm` 的轨道，比主唱低 5 dB：

- 是运行时的喵谱子，没有渲染音频：`levels/music/patterns/harm_<曲子>.json`，`tools/music_gen/make_harmony_patterns.py` 按规则写出来的。
- 写法：每半小节按和弦，在反拍的八分音符上放三度和五度（C4～B4，在主旋律下面），短音；主旋律在那一格有音就让开。
  主旋律一路都是八分音符的曲子（山魔王、康康舞）反拍上没空，改成每半小节一个长一点的音。
- 在哪响：猫唱主旋律的那几档（上升关的欢乐颂、洗衣机的小花、拍地球的山魔王和康康舞、第 3 关的土耳其进行曲和康康舞）。
  第 1 关的迪斯科主题还没有。
- 每首可以单独指定哪只猫唱、多响（脚本里的 `CAT` / `GAIN_DB`）。欢乐颂固定用最柔和的那只低音猫，再低 3 dB：
  自动选猫时第二句换到了一只更亮的猫，盖过了主唱。
- 按游戏里的播放方式离线出试听：`make_harmony_previews.py`。

### 听出来的几条经验（改主唱时照着做）

这些都是试听之后一条条改出来的，脚本是 `tools/music_gen/compose_classics.py`：

1. **和声的猫不要自动换。** 和声是垫在下面的，换到一只亮的猫就抢戏。固定一只柔和的。
2. **"整声喵"的主唱（flow）里，连着两个一样高的高音合成一个长音。** 高音会叠一层硬切的喵，两个音各切一次就碎了
   （欢乐颂的 G–G）。只合并高音（G5 以上）；正常的同音重复不合并，不然旋律的节奏就变了。
3. **乐句结尾"一短一长"要保留**（欢乐颂的 D–D：短的弱起 + 长音）。不要合并成一个音；短音提前 0.05 秒收住，
   让两个音分得开。长音是一声完整的 MIAO，不要 mi-mi-mi 连击。
4. **鬼畜版里快音会闷，是因为猫叫的开头是闷的。** 每个音都从叫声的开头放起；有的猫开头是一小段 "m"，后面才亮成
   "iao"。长音来得及唱到亮的地方，八分音符（0.19 秒）只放得完闷的那一段。
5. **不要按"音高最接近"去挑猫来唱快音**：量过，音高最接近的那只恰好开头最闷。挑猫要看开头亮不亮
   （前 0.18 秒里 2～8 kHz 的能量占比：有的猫 87%，有的 0%）。
6. **最后用的办法是叠 mi**：还是原来那只猫唱，每个音的开头叠一声小猫的 "mi"（快音和长音都叠）。
   土耳其进行曲这么做的（歌的 `mi_attack=True`，`CAT_QUICK` 默认 `own+mi_all`）；六种做法的对比试听是 `make_quick_tests.py`。
8. **鬼畜叠在猫主唱上面时，主唱要让开。** 两条猫旋律一起全音量会乱。现在 kiai 轨上响的是鬼畜（片段名里有 kichiku）
   而且 lead 轨也在响的时候，lead 自动低 6 dB（`music.gd` 的 `KIAI_DUCK_DB`）；kiai 轨上是乐器就不让。
9. **欢乐颂的主唱留着"整声喵"版**（试过鬼畜版和两种叠在一起的，定的还是整声喵：这首慢，要连着唱的感觉；鬼畜在升档和
   fever 的时候叠上来）。
7. **改主唱先出几种试听再定**，不要猜着改一版进游戏：听感的问题数据只能帮着定位，定不了好坏。

### 猫合唱只用在慢的段落（2026-11-16 试听定的）

想让披萨后段的猫叫有"合唱的饱满感"，做了三轮试听（`tools/music_gen/make_cat_harmony_tests.py`）：

- 快的名旋律（160 BPM 的八分音）上，不管是每个音都跟唱三度/六度，还是 24 只猫齐唱加大厅混响、跟底鼓呼吸、整体压缩，都是乱。原因在采样：猫叫要过一小会儿才从"mi"滑到稳定的音高，八分音只够唱出噪声多、音高还在滑的开头，叠多少只都锁不成和弦。测出来猫叫的能量在 800 Hz–3 kHz，基音很弱，所以也补不了中低频。
- 四分音或更长的段落（四步下行）上同样的做法就好听：`tools/music_gen/make_choir_stems.py` 渲染 `<曲子>_C_choir_<小节>b.wav`，放在猫和声那一轨。
- 所以：合唱只给慢段落；快段落要让猫明显，靠的是音量平衡（把盖住它的方波压下去），不是再叠猫。

片段现在可以带自己的 `"gain_db"`（加在所在那一轨的音量上），生成脚本里是 `t(id, 文件, 组, 增益)`。
